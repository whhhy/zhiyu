  （这里**不写节数** —— 2026-10-12 刚因为加了第十节、下一行的「十一节」就过期了；
  节数会漂，而「有哪些页」不会。）
- `test-index.md` —— **测试索引（自动生成，勿手改）**：套件与项数来自 `_all.log` 的
  **真实运行结果**，所以不会漂；跑完用 `npm run test:index` 重新生成。
  另起一份是因为 README 里那份 npm 清单有 62 行带坏字、还有粘连的长行。
- `invite-design.md` —— 协作邀请的设计与边界（发/收两种视角、权限、撤回）。

  那是**挂在 `/knowledge/` 子路径下**的实机图，配 nginx 那份验证过的配置用的就是它。
- `evidence/` —— 部署验收的两份日志（`deploy-accept-node.log` / `-docker.log`）。

  具体项数会随验收步骤增删变化，**以日志里那行「结果：N 通过 / M 失败」为准** —
  这里不复述数字，免得下次加了步骤又对不上（这种过时的硬编码最难发现）。

## 部署手册去哪找

`README.md` / `DEPLOY.md` 在 2026-10-05 的编码事故里有乱码残留。

### 换新版本时顺手改掉这几条（都是 2026-10-12 实证出来的）

1. `DEPLOY.md`：导入「**整体替换**只清当前用户自己写的东西，不会清空别人的内容**」——
   这条**只对普通成员成立**。平台 owner 走 `denyReason` 的早退放行，
   选「整体替换」会把包里没有的**知识库、目录、评论全部删掉**（文档进回收站还能救，那三类不能）。
2. `README.md`：测试项数与 `npm run test:` 清单 —— 已过时，
   以 [`docs/test-index.md`](test-index.md) 为准（那份是从 `_all.log` 的真实结果生成的）。
3. 任何提到「迁移脚本」的地方 —— **本项目没有迁移脚本**，
   表结构在启动时自动补列（`server/db.ts` 里的幂等 `ALTER TABLE`）。  

**完好无损的内网部署手册是仓库根目录的 [`RUNBOOK.md`](../RUNBOOK.md)** ——
覆盖最短路径、环境变量、首次部署 vs 已有数据、口令这道门、子路径反代（含**真跑过**的 nginx 配置）、
反向代理、备份、验收、升级、常见坑。
它的环境变量表与源码的一致性由 `test-runbook-env.mjs` 守着（双向核对）。

## 为什么要有它

本项目是「1:1 复刻语雀」，而**凭记忆复刻会持续出错**。同一个项目里
实测已经推翻过我的假设至少七次：

1. 知识库设置左栏不是平铺一列，是**分两组**
2. 「知识库信息」在最前、「统计」在「目录管理」**之前**
3. 删除知识库在「**更多设置**」里，不在安全设置页
4. 面包屑该**删**不该补
5. 「开始」是**导航项**不是组名
6. 是「获取灵感」不是「取得灵感」
7. 知识库首页**没有 tab**，是欢迎页 + 完整目录（我原先记成「缺外层 tab」）

每一条都写在这里，改代码时对着它做。
